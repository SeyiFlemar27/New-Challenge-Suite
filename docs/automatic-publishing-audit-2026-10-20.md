## Shared publishing policy

The old journey was complete → submit → pending review → Admin decision → visibility. The new journey is complete → Publish → essential server checks → atomic published state → immediate public eligibility. Discovery remains conditional on actual public/private-preview visibility and moderation status, not registration/payment readiness.

Tournament bracket generation after all slots fill, the five-second activation countdown, required match submission/voting durations, and background lifecycle safeguards remain in place; publication does not start a competition before those conditions hold.

Exactly three creator outcomes are used: **Published**, **Needs attention** with a real field/dependency error, and **Held for moderation** for a persisted credible restriction. Technical failures remain technical failures and do not create safety allegations. Duplicate/concurrent publication uses current record versions and an idempotent transaction; publication events and notifications are deduplicated.

Retained checks: authentication, ownership/current permissions, subscriptions and lifetime free quota, Enterprise limits, genuine media ownership/bytes/MIME/decoding, JPEG/PNG/WebP 10 MiB image policy, supported optional video verification, meaningful chronological/venue/capacity/bracket configuration, actual provider-confirmed creator funding, ledger/settlement/refund/dispute controls, explicit account restrictions, Community Guidelines and human reports/moderation. No AI content screening, risk score, broad keyword filter, aspect-ratio gate or visual-quality threshold was introduced. Retired age/location eligibility was not reintroduced.

## Admin simplification and safety

The challenge-review endpoint and workspace now operate on `challengeModerationCases`, rather than routine submissions. Reports, credible persisted restrictions, suspected fraud, removals and creator appeals are investigated with mandatory reasons, explicit confirmation, version checks and audit logs. A user report alone does not remove content. Hold/remove affect public visibility; release freshly revalidates media/funding/account restrictions. Releasing a held unpublished draft does not itself publish it.

Routine approval controls/counters/notifications were removed from the active challenge workspace. Compatibility approve/reject/request-changes publication actions return 410. Winner decisions, payouts, refunds, disputes, challenge operations and controlled material changes remain. Sponsor and Enterprise application approval handlers were not changed. Existing single-Admin permission enforcement is reused.

An explicit investigated release also clears its resolved content-level fraud flag, recording the previous flag in the audit. Otherwise an unpublished draft would immediately re-enter the same resolved hold. Account restrictions and financial restrictions are not cleared by this action; they remain independent safeguards. A regression verifies the full hold → reasoned human resolution → creator Publish sequence.

## Editing after publication

Published-details endpoints allow a strict descriptive/promotional whitelist with optimistic version checks and audit. Replacement media uses the real verification pipeline. Sensitive financial amounts, entry/ticket terms, schedule, rules and participant commitments cannot pass through this endpoint. Existing Live controlled participant-notification/refund/change-proposal flows remain available. Harmless text changes do not need editorial approval.
